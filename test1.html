The Problem & The Solution

The Problem

Large Language Models (LLMs) like OpenAI's GPT are trained on vast, static datasets. This leads to several limitations:

  • Knowledge Cutoff: The model doesn't have access to the most recent information.
  • Hallucinations: The model may generate incorrect or invented information.
  • Lack of Specificity: The model cannot answer questions about your private or proprietary data.

The Solution: RAG

Retrieval Augmented Generation (RAG) is a technique that combines an LLM with an external knowledge base.

  • Real-time Information: RAG provides up-to-date data from your own sources.
  • Factual Grounding: It minimizes hallucinations by grounding responses in facts.
  • Context-Aware: It allows the LLM to provide accurate answers about your specific data.

How It Works: The RAG Flow

Ingest

Load your documents (PDFs, text files) into the system.

Split

Break large documents into smaller, manageable chunks.

Embed

Convert text chunks into numerical vectors (embeddings) using an embedding model.

Store

Store the embeddings and original text in a vector database like pgVector.

Data Preparation Phase
Retrieve

Find the most relevant text chunks based on the user's query.

Generate

Use the retrieved chunks as context for the LLM to generate a final answer.

At Query Time

Architectural Patterns

Flow 1: Direct LLM Call

User Prompt
LLM
LLM Response

The LLM generates a response solely based on its pre-trained knowledge, without external context.

Flow 2: RAG Implementation

User Prompt
Embedding Model
Vector DB (pgVector)
LLM + Context
RAG Response

The LLM augments its response with relevant context from the vector database.

Configure your `application.properties` file with API keys and database details.

spring.ai.openai.api-key=${OPENAI_API_KEY}
spring.ai.openai.embedding.model=text-embedding-ada-002

# PGVector
spring.datasource.url=jdbc:postgresql://localhost:5432/rag_db
spring.datasource.username=user
spring.datasource.password=password
spring.ai.vectorstore.pgvector.initialize-schema=true

3. Data Ingestion

Create a service to load and ingest your documents into the vector store.

@Service
public class DocumentLoaderService {

    private final VectorStore vectorStore;
    private final Resource docsResource;
    private final PdfDocumentReader pdfReader;

    public DocumentLoaderService(VectorStore vectorStore, @Value("classpath:/docs/spring-ai.pdf") Resource docsResource, PdfDocumentReader pdfReader) {
        this.vectorStore = vectorStore;
        this.docsResource = docsResource;
        this.pdfReader = pdfReader;
    }

    public void ingestDocuments() {
        if (!vectorStore.getVectorStoreMetadata().isInitialized()) {
            vectorStore.init();
        }

        DocumentReader documentReader = new PdfDocumentReader(docsResource);
        List<Document> documents = documentReader.get();
        vectorStore.add(documents);
        System.out.println("Documents ingested into Vector Store successfully!");
    }
}

4. AI Controller

Expose a REST API to handle user questions and generate responses.

@RestController
public class AiController {

    private final ChatClient chatClient;

    public AiController(ChatClient chatClient) {
        this.chatClient = chatClient;
    }

    @GetMapping("/chat")
    public String chat(@RequestParam(value = "message", defaultValue = "What is Spring AI?") String message) {
        return chatClient.call(message);
    }
}

5. RAG Service

The core service that orchestrates the RAG flow using Langchain4j.

@Service
public class RagService {

    private final ChatLanguageModel chatModel;
    private final EmbeddingModel embeddingModel;
    private final PgVectorEmbeddingStore embeddingStore;

    public RagService(ChatLanguageModel chatModel, EmbeddingModel embeddingModel, PgVectorEmbeddingStore embeddingStore) {
        this.chatModel = chatModel;
        this.embeddingModel = embeddingModel;
        this.embeddingStore = embeddingStore;
    }

    public String chatWithRag(String query) {
        // Step 1: Ingest/Load (done separately)
        // Step 2: Split (done by Langchain4j)
        // Step 3: Embed (done by Langchain4j)
        // Step 4: Store (done by Langchain4j)

        // Step 5: Retrieve relevant documents
        ContentRetriever contentRetriever = new EmbeddingStoreContentRetriever(embeddingStore, embeddingModel);
        
        // Step 6: Create the RAG chain and generate a response
        PromptTemplate promptTemplate = PromptTemplate.from("""
            Answer the user's question based on the provided context only.
            Context: {context}
            Question: {question}
        """);

        AiService aiService = new AiService(chatModel, contentRetriever, promptTemplate);
        
        return aiService.chat(query);
    }
}

Key Takeaways

Spring AI

A Java framework that simplifies building AI applications by providing a portable API for various AI models and services.

RAG

A powerful technique that combines LLMs with your private data to provide grounded, up-to-date, and accurate responses.

pgVector

A PostgreSQL extension that turns your relational database into a powerful vector store for efficient similarity search.

OpenAI

Provides powerful LLMs (like GPT-4o) and embedding models to handle the core generation and embedding tasks.

Langchain4j

A Java library that provides the core orchestration and tooling to simplify the RAG workflow, similar to its Python counterpart.

Building Blocks

These technologies work together to create a robust and scalable solution for creating intelligent applications grounded in your own data.
